# Claude Handover Workspace

This `.claude` folder serves as the onboarding and documentation hub for Claude Code development on the Doctoral Research & Journal Publication Assistant repository.

## Document Index

| File | Purpose |
|------|---------|
| **CLAUDE.md** | Instructions, preferences, and context for Claude Code when working in this repository. This file guides the AI assistant on project conventions, coding standards, and workflow patterns. |
| **PROJECT_MEMORY.md** | Long-term project context and foundational knowledge. Contains essential information about the project's purpose, architecture, and key design decisions that should persist across sessions. |
| **HANDOVER.md** | Developer handover notes for transitioning ownership or context between team members. Includes current state, priorities, and critical information for seamless transitions. |
| **ROADMAP.md** | Project roadmap outlining near-term, medium-term, and long-term objectives. Maps out feature goals, milestone targets, and strategic direction. |
| **ARCHITECTURE_RULES.md** | Rules and constraints governing architectural decisions. Defines patterns to follow, anti-patterns to avoid, and structural guidelines for code organization. |
| **DEVELOPMENT_GUIDELINES.md** | Coding standards, workflows, and best practices for development. Includes style guides, testing requirements, and contribution conventions. |
| **DECISIONS.md** | Log of significant technical and architectural decisions made during development. Each entry should include rationale, alternatives considered, and decision outcome. |
| **KNOWN_LIMITATIONS.md** | Documented constraints, bugs, and known issues in the current implementation. Helps developers understand what doesn't work and why. |
| **FUTURE_ENHANCEMENTS.md** | Ideas and proposals for future features and improvements. A backlog of potential enhancements that align with the project roadmap. |
| **SESSION_LOG.md** | Chronological log of development sessions, including completed tasks, pending work, and session summaries for continuity. |

## Usage

- Review `PROJECT_MEMORY.md` and `ARCHITECTURE_RULES.md` before making changes to understand the project context and constraints.
- Consult `DEVELOPMENT_GUIDELINES.md` for coding standards and workflows.
- Log significant decisions in `DECISIONS.md` and update `SESSION_LOG.md` after each work session.
